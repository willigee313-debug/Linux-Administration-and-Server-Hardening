# Prevent Root Login via SSH

## Overview

Restricting direct root login over SSH is one of the highest-value, lowest-effort hardening steps you can apply to a Linux server. The `root` account is a universal, well-known target: every SSH brute-force bot on the internet tries `root` first. By forcing administrators to authenticate as an unprivileged user and then escalate with `sudo`, you gain **individual accountability** (each admin has their own credentials and audit trail) and remove the single most valuable password from the attack surface.

This note covers disabling `PermitRootLogin` via the main config file or a drop-in override, validating that no conflicting directive re-enables it, and verifying the change.

> [!IMPORTANT]
> Setting `PermitRootLogin no` is required by the **CIS Benchmark for Linux (SSH Server)** and recommended by **NIST SP 800-53 (AC-6, least privilege)**. Always confirm you have a working, `sudo`-capable non-root account **before** applying this change, or you may lock yourself out.

## Concepts

`PermitRootLogin` is an `sshd` directive that governs whether the `root` user may authenticate directly. Its accepted values:

| Value | Behaviour |
| --- | --- |
| `yes` | Root may log in with any permitted method (password or key). Discouraged. |
| `no` | Root may not log in by any method. Recommended baseline. |
| `prohibit-password` | Root may log in only with public-key / non-interactive methods, never a password. Default on many modern distros. |
| `forced-commands-only` | Root may log in with keys, but only to run a `command="..."` pinned in `authorized_keys` (useful for automated backups). |

On current OpenSSH builds, the shipped `/etc/ssh/sshd_config` typically ends with an `Include /etc/ssh/sshd_config.d/*.conf` line. **Drop-in files in that directory are parsed in lexical order, and the first matching directive wins.** This is why validation (below) matters: a stray file setting `PermitRootLogin yes` can silently override your intent.

## Configuration

You can define the directive in either the main configuration file or a dedicated drop-in override file. The drop-in approach is preferred on modern systems because it survives package upgrades and keeps local policy separate from vendor defaults.

### Option 1 — Main config file

```bash
vim /etc/ssh/sshd_config
```

> Add or update:

```conf
PermitRootLogin no
```

### Option 2 — Drop-in override file (preferred)

Create or edit a drop-in config file for modular management:

```bash
vim /etc/ssh/sshd_config.d/01.permitrootlogin.conf
```

> Add the directive:

```conf
PermitRootLogin no
```

> [!NOTE]
> If this file was generated by an installer (e.g., Anaconda), feel free to edit or delete it as appropriate for your use case.

## Commands

Key operations for applying and confirming the change:

| Task | Command |
| --- | --- |
| Search drop-in dir for the directive | `grep -ri "PermitRootLogin" /etc/ssh/sshd_config.d/` |
| Search all config files | `grep -r "PermitRootLogin" /etc/ssh/sshd_config*` |
| Restart the daemon | `systemctl restart sshd.service` |
| Test as a non-root user | `ssh -p 2222 armour@192.168.1.38` |

## Validate Configuration

Because drop-in files can override the main config, confirm no other file re-enables root:

```bash
grep -ri "PermitRootLogin" /etc/ssh/sshd_config.d/
```

```bash
grep -r "PermitRootLogin" /etc/ssh/sshd_config*
```

> Make sure no other config file sets it to `yes`.

## Restart SSHD

After modifying the config, restart the SSH daemon so the new policy takes effect:

```bash
systemctl restart sshd.service
```

> [!TIP]
> Validate syntax before restarting with `sshd -t`. A configuration typo can leave `sshd` unable to start, cutting off remote access.

## Test SSH Access

Use a non-root user to test connectivity (e.g., on a custom port):

```bash
ssh -p 2222 armour@192.168.1.38
```

> Attempting to log in as `root` should now result in a **"Permission denied"** error.

## Examples

A complete, minimal hardened configuration and its matching drop-in override.

### `/etc/ssh/sshd_config`

```conf
Include /etc/ssh/sshd_config.d/*.conf
Port 2200
ListenAddress 192.168.1.32
PermitRootLogin no
AuthorizedKeysFile	.ssh/authorized_keys
Subsystem	sftp	/usr/libexec/openssh/sftp-server
```

### `/etc/ssh/sshd_config.d/01.permitrootlogin.conf`

```conf
PermitRootLogin no
```

## Security Considerations

- **Never disable root login without a tested escalation path.** Confirm a non-root account exists in the `wheel`/`sudo` group and can run `sudo -i` before restarting `sshd`.
- Pair `PermitRootLogin no` with `PasswordAuthentication no` and key-based auth to eliminate password brute-forcing entirely.
- Restrict who may connect at all with `AllowUsers` / `AllowGroups`, and rate-limit failed attempts with `fail2ban` or `sshd` `MaxAuthTries`.
- Keep an out-of-band console (IPMI/serial/cloud console) available in case an SSH change locks you out.

## Troubleshooting

| Symptom | Likely cause | Resolution |
| --- | --- | --- |
| Root can still log in | A drop-in file sets `PermitRootLogin yes` and is parsed first | Run the `grep -ri` check; remove/fix the conflicting file |
| `sshd` fails to restart | Syntax error in a config file | Run `sshd -t` to see the offending line |
| Locked out entirely | No working non-root account | Use console access to re-enable a sudo user |
